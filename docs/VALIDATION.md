# 离线验证 0.1.0

目前测试了独立库和两个模拟宿主，尚未接入真实引擎。下面记录已做过的检查，脚本和子智能体复检都在本机离线运行。

| 检查 | 结果 |
| --- | --- |
| 行为测试 | 42 项通过，覆盖控制器、真实执行回执、目标／模式／生命变化、移动、狙击、部署、名单、装备和聊天 |
| 算法对照 | 35,350 次比较通过，使用合成输入检查时间窗口、狙击、目标保持和可选瞄准 |
| TypeScript | 5.9.3，启用 strict、exactOptionalPropertyTypes、noUncheckedIndexedAccess，关闭 skipLibCheck；公共导出调用和预期类型错误检查通过 |
| 独立目录 | 复制源码后运行全部测试、编译和示例，仅使用仓库文件、Node.js 和锁定的开发依赖 |
| 两个模拟宿主 | 使用不同长度、角度单位和坐标轴，得到相同控制结果；示例发射 22 次，重复运行结果一致 |
| 故意改错 | 将冲锋枪窗口改短、关闭许可过期判断，两次都触发了预期的测试失败 |
| 来源检查 | 核对已保存参考资料和许可，检查精确 token 片段及仓库文件清单；文件摘要见 FILES.json |

独立复检时发现并修正了旧移动回执干扰新组、开始回执晚到、旧 `stopped` 确认新停止操作、跨回合聊天入队、库瞄准与狙击组合，以及移动命令晚于路径证据过期的问题。

狙击测试按同步回执的调用顺序执行。`beforeDischarge` 只检查许可，不预留一发；实际出弹后必须同步 `recordShot`，在下一次检查或 `update` 前消费许可。自动武器可以在下一帧交付出弹结果。

来源检查只覆盖实际保存的参考材料。比对时去掉注释、空白，再检查连续 30 个相同 token，结果没有达到这一阈值的匹配。30 是本次筛查设置，这种方法也查不到任意改名、语义重写或未保存的材料。完整历史原创性仍超出这项检查的结论。参考项目及许可见 [ACKNOWLEDGEMENTS.md](../ACKNOWLEDGEMENTS.md) 和 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)，本库代码的许可见 [LICENSE](../LICENSE)。

真实引擎的瞄准、导航、物理子弹、ABI 和性能尚未测试。两个适配示例也尚未制作成 Unity、Unreal 或 Godot 插件。移动默认值为 0.9 米、0.18 米／秒，接入时需要按游戏尺度和移动速度调整。上面的算法对照结果适用于所列的合成输入。
